# Suikoden RNG Tool

Browser tool for the PS1 game *Suikoden 1* (speedrun/RNG-manipulation community). Predicts RNG-driven events
(encounters, item drops, stats, NPC movement, etc.) and finds the current RNG seed from observed encounters.
Live at https://ak505188.github.io/Suikoden-RNG-Tool/ (GitHub Pages, `npm run deploy` → `gh-pages -d build`).
`README.md` is mostly a write-up of how the game's RNG works (32-bit RNG at `0x00009010`, what advances it, method pseudocode) — read it for game-logic context.

## Stack
- Vite 8 + `@vitejs/plugin-react` (config: `vite.config.mjs`, `index.html` at the repo root), Node 22 (`.nvmrc`). React 18 (`createRoot` in `app/index.jsx`; hooks + some class code), JSX in `.jsx` (Vite requires `.jsx` for JSX and rejects type annotations in source).
- UI: `semantic-ui-react` 2 (its React 18.3 console warnings about `defaultProps` and `findDOMNode` come from the library, not this repo), `react-virtualized` tables, `styled-components`, plain `.css` files next to their components (scope selectors to a class, as `features/experience/Experience.css` does; bare element rules apply app-wide).
- Routing: `react-router-dom` v5 `HashRouter`. State is passed form → result via **URL query params** (`/sequence/result?rng=..&iterations=..`); the result page recomputes from the params.
- Redux (`redux`, `redux-actions`) is used only by Run Assistant.
- Game logic lives in the external package **`suikoden-rng-lib`** (git dependency, `ak505188/Suikoden-RNG-lib#battle-simulator`; `.npmrc` sets `allow-git=all` because npm 12 blocks git deps by default): `RNG` (`raw`, `rand`, `next()`, `jump(n)`, `peek()`, `clone()`, `seed`, `count`), `Areas`/`Area`, `Helpers`, roll checks (`isCliveAppearance(rand)`, `countWheelAttempts(rng)`, ...), stats, `Kaku`, chinchironin, assassin. Import from the package root, or from the `suikoden-rng-lib/encounters` entry (new `AREAS`/`generateEncounters` API replacing the deprecated root `Areas`; every tool is migrated, so nothing uses the old root `Areas`, `Area` or `Helpers.areaNamesWithRandomEncounters` any more). The package has an `exports` map, so no deep imports. This repo is the UI on top of it.
- Absolute imports from `src/` for `app/`, `features/`, `shared/`, `test/` (aliases in `vite.config.mjs`, mirrored in `jsconfig.json`).
- Worker: `features/rng-finder/findRNG.worker.js`, loaded with Vite's `?worker` import in `RngFinder.jsx`. Table filtering uses the in-repo `shared/table/SearchIndex.js` (replaced `js-worker-search`, whose bundle crashes as an ES module).
- Commands: `npm start` (dev), `npm run build` (output in `build/`), `npm run preview`, `npm test` (Vitest, jsdom), `npm run deploy` (gh-pages from `build/`). Lint/format: `npm run lint` (ESLint 9 flat config in `eslint.config.mjs`; capped at 9 because `eslint-plugin-react` doesn't support 10 yet), `npm run format` / `format:check` (Prettier, config in `.prettierrc.json`, same as the lib). Branches: work on `dev`, `master` is main. Base path is `/Suikoden-RNG-Tool/` (GitHub Pages).
- Local lib development: `npm install` reinstalls the lib from git. To use a local checkout, replace `node_modules/suikoden-rng-lib` with a symlink to it (e.g. `ln -s ../../Suikoden-RNG-lib node_modules/suikoden-rng-lib`) after each install.

## Layout
- `index.html` – Vite entry page. `src/app/` – `index.jsx` (app entry, HashRouter), `App.jsx` (all routes, wrapped in `ErrorBoundary.jsx` so a page that throws shows a message and keeps the navbar), `Navbar.jsx`, `Home.jsx`, `index.css`.
- `src/features/<tool>/` – one flat folder per tool: `<Tool>Form.jsx` (inputs → `submitTo(history, path, params)`), `<Tool>Result.jsx` (read the URL with `useQueryParams(SCHEMA)`, show `InvalidLink` if it reports problems, then compute) + `<Tool>Table.jsx` (display), plus tool-specific `lib.js`/CSS. `index.js` exports `{ Form, Result }` (`experience` exports its single page as default). Tools: `encounters`, `itemdrops`, `sequence`, `npc-movements`, `experience`, `chinchironin`, `assassin`, `kaku`, and `stats` (sub-tools `starting-stats/`, `level-ups/` with the same file pattern; `stats/index.js` exports `StatsInfo` hub page and the sub-tool `*Form`/`*Result`).
- `src/features/rng-finder/` – the RNG finder page (`RngFinder.jsx`, `Status.jsx`) plus the brute-force seed finder (scans half the RNG cycle, 2^31 states, for an observed encounter sequence and lists every match): `findRNG.js` (scans the RNG cycle with per-area lookup tables built from the lib's `isBattle`/`encounterIndex`, in a small `scan()` hot loop that inlines the lib's `LCG` step and must keep that and the lookup tables as module-local consts (V8 reads imported bindings from memory on every use, which halves the speed in plain mode); options `maxMatches` (1 stops at the first match), `maxSteps`; the fights after the first follow the game's rule that a battle spends the next RNG call on its group, but any battle value can be the first fight, so a value that rule skips is also tried as a start; a search covers half the RNG cycle (2^31 steps) because the game ignores bit 31, so a match and `raw ^ 0x80000000` are twins that `rngPair.js` shows together; each match also carries the first possible RNG and gap, found by walking back with `prev()`), the web worker entry (`findRNG.worker.js`, which only imports `suikoden-rng-lib/encounters` to keep the worker small) and progress class `SearchStatus.js`.
- `src/features/run-assistant/` – the largest tool: live run companion with Redux (`actions/`, `reducers/`, `controls/` incl. hotkeys + config modal, `Table.jsx`); `buildState.js` builds its state from the URL, `groups.js` shapes the new formations into the `{ name, enemies, champVal }` groups the reducers and buttons use, with each enemy's picture from the lib's `suikoden-rng-lib/enemy-images` (data URLs, so they go straight into `src`).
- `src/shared/` – reusable code: `form/` (`InputRNG`, `InputIterations`, `AreaGroupPicker` (area + enemy group dropdowns, used by Item Drops and Experience), `DraftNumberInput` (a number box that can be emptied and retyped while only valid values reach state; use it for any number box that drives a computation), ...), `ui/` (`DoubleListSelector`, `ImportModal`, `InvalidLink`), `form/submitTo.js` (sends a form's values to its result URL), `lib/params.js` + `lib/useQueryParams.js` (read a result page's query against a schema of `int`/`string`/`bool`/`list`/`oneOf`; a parameter with no `default` is required and a missing or bad one is reported as a problem), `table/` (generic searchable/filterable/exportable virtualized table used by results), `lib/` (`encounters.js`: helpers over the lib's new `suikoden-rng-lib/encounters` entry, e.g. `ENCOUNTER_AREAS`/`FIGHT_AREAS`, `areaId`/`findAreaById` for URL ids, `areaFormations`, `formationLevels` (names come from the lib's own `formationName`); `items.js`: `itemName`).
- `public/` – static files (includes a `service-worker.js` that unregisters the old CRA service worker in returning browsers). `build/` – generated output (gitignored).

## Adding a tool
Create `features/<tool>/` with `<Tool>Form.jsx`, `<Tool>Result.jsx`, `<Tool>Table.jsx` and an `index.js` exporting `Form`/`Result`, then add two `<Route>`s in `app/App.jsx` and a link in `Navbar.jsx`/`Home.jsx`. Give the form a disabled submit until its required choices are made, give the result a params schema, and add the tool's result URLs to `src/app/routes.test.jsx`, which checks every result page against good, empty and bad links.
